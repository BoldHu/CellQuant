# 阶段门槛、迁移决策与论文标准

版本：2026-11-15。适用对象：以 SpinQuant 为基础、仅改变全局 R1 构造的双侧动态量化胞元研究。

## 1. 如何使用这些门槛

本文件中的数字是项目的**预注册投入决策标准**，不是文献已经测得的结果，也不是 ICLR/NeurIPS/ICML 的录用标准。先冻结门槛，再查看最终测试结果。允许记录方法失败，禁止通过删除失败层、换种子、改指标或调高容差把失败改成通过。

机读版本为 `configs/gate_rules.json`。Notebook 应读取该文件，而不是再写一套独立条件。未测量、缺文件、占位符、OOM、未实现 adapter 都必须得到 `INSUFFICIENT_EVIDENCE`，不能用零值代替，也不能默认通过。实际超出门槛为 `FAIL`。全部必需条件满足且至少一条允许路线满足为 `PASS`。G4 的通过只表示 `paper_candidate`。

阶段严格区分：

| 阶段 | 回答的问题 | 通过后可做什么 |
|---|---|---|
| G0 | 数学参考实现是否正确？ | 开始真实层面板实验 |
| G1 | 同一全局旋转是否在真实层上有可迁移的价值？ | 迁移到 AutoDL，运行有限预算的完整模型 canary |
| G2 | 真实 Transformer 等价修正、GPTQ 和完整模型是否保留收益？ | 准备完整主实验协议 |
| G3 | 环境、协议、复现、预算与断点恢复是否就绪？ | 启动完整实验矩阵 |
| G4 | 结果是否支撑清晰且有竞争力的论文主张？ | 完成方法论文；仍需判断新颖性和投稿定位 |

**G0 通过不能直接启动全量；G1 通过也只批准 AutoDL canary，不批准自动运行全部模型和种子。** Colab 资源不足以收集真实层证据时，记录 `RESOURCE_BLOCKED`，只做一次有限硬件/数据提取 probe；这不算 G1 通过。

## 2. 必须固定的比较边界

- 新方法拟合一个 `global_r1`。每个模型最终只有一个 Q，所有层使用同一 Q。不同层独立找到各自最好角度不能用来通过 G1。
- 输入侧采用 `W Q.T` 和 `Q X`；down-proj/o-proj 输出侧采用 `Q B`，不能错误地当成右乘更新。主实验固定 R2/R3/R4。
- 两类 SpinQuant 基线必须区分：`SpinQuant-R1` 为控制实验（固定 R2，仅优化 R1）；`SpinQuant-stock` 为尽量遵循公开训练方式的实际竞争者（可学习 R1/R2）。不得把前者的结果标成完整官方 SpinQuant。
- G1 中最强对照为同样 Givens 参数化、同样有限面板目标的 STE/AdamW、角度网格和固定尺度事件搜索中表现最好的一个。所有方法在同一 GPU/CPU、相同壁钟预算下比较；同时记录候选评估次数。只匹配次数不足以声称同计算成本。
- G2/G4 所称 SpinQuant 为**自己复现且协议锁定**的结果，不能使用跨论文数值代替。若只能运行 R1 控制版，阶段证据应明确不足，不能跳过实际竞争基线。
- 校准种子改变校准采样和初始化；同一 seed 的多个 token 不是独立重复。最终主表至少 3 个校准种子。
- 理论只覆盖冻结面板和指定 RTN/固定裁剪分支。GPTQ 是最终独立验证；不得把 RTN 定理写成 GPTQ 最优性。
- 论文结果、自己的 GPU 实测、小矩阵 CPU 实测、尚未运行的计划分别存放并标注来源。

## 3. G0：数学与 CPU 参考实现

至少 3 个随机种子、20 个小矩阵/分组测试用例，包括组内配对、跨组配对、零组、当前量化算子可表示区间端点、同时阈值事件以及输出侧更新。额外fixed-clipping等扩展未实现时标明范围，不把可选扩展当主AbsMax路线的必需条件。

误差定义：

\[
e_{\rm prod}=\frac{\|WQ^TQX-WX\|_F}{\max(\|WX\|_F,10^{-12})},\qquad
e_{\rm orth}=\frac{\|Q^TQ-I\|_F}{\sqrt d}.
\]

| 指标 | G0 门槛 | 解释 |
|---|---:|---|
| FP64 小矩阵乘积相对误差 | ≤ 1e-10 | 检查转置、旋转方向和配对补偿 |
| FP64 正交残差 | ≤ 1e-10 | 此处是数值阈值，不是机器精度严格为零 |
| 胞元预测的归一化输出损失绝对误差 | ≤ 1e-9 | 从解析系数预测，与直接量化比较 |
| 完整搜索与筛选搜索的损失相对差异 | ≤ 1e-7 | 平坦胞元可能有多个最优角，不强求角度相等 |
| 预算违反次数 | 0 | 容差在测试配置中预先固定 |
| 接受更新后目标上升次数 | 0 | 必须用真实量化算子复核 |
| 边界/舍入规则覆盖 | true | 检查 actual boundary，不只检查左右极限 |

G0 不包含完整 Transformer 的浮点等价；后者是 G2 的前置条件。当前交付包的 CPU 检验结果不等于完整模型已经通过。

## 4. G1：Colab 真实层 pilot

### 4.1 最小真实层设计

- 首选 LLaMA-2-7b-hf，固定 model/tokenizer revision。若 Colab 连单层流式采集都无法完成，可用较小 LLaMA 兼容模型做工程 smoke，但不能代替 7B 的 G1 证据。
- 选择层 0、15、31，各选 q-proj、up-proj、down-proj，共 9 个位置。可同时保存 o-proj 做方向性附加检查。
- 2 个校准种子；每个 seed 使用相同的 9 个位置，拟合同一个全局 Q。
- 校准和 held-out 至少各来自 8 条独立序列；采集时保留长度 2048 的上下文，可分别抽取每面板 128 个拟合 token、256 个 held-out token。
- 可以抽权重输出行和 token，但每条入选行/token 必须保留完整量化组。不得截断 d 后把截断部分重新当成量化组。
- 输入侧大矩阵可抽 64–128 个输出行；输出侧 down-proj 的两整行变化必须正确处理，不能套用仅两个组成员变化的筛选引理。
- 初始角度预算 K=32/128；只有时间可控再扩展。学习同一 Q 的多个坐标对，不能从独立最佳角度的集合推断最终 Q 的效果。

对每个位置先在两个 seed 上计算 held-out NMSE 改善，再按位置汇总。不能让某个 token 数量极多的层支配整体统计。

### 4.2 通过路线 A：准确率潜力

以下全部满足：

1. 相比固定随机 Hadamard，held-out NMSE 相对下降的跨位置中位数 ≥ **10%**。
2. 相比同预算最强 STE/网格/固定尺度搜索，下降中位数 ≥ **5%**。
3. 至少 **6/9** 个位置优于最强对照。
4. 任一位置相对最强对照的退化不超过 **10%**。
5. 两个 seed 的聚合 held-out 目标都改善；不能靠一个 seed 的极大收益掩盖另一个失败。

### 4.3 通过路线 B：效率潜力

以下全部满足：

1. 相比 Hadamard，held-out NMSE 中位数至少改善 **5%**。
2. 相比最强搜索对照，NMSE 中位数退化 ≤ **2%**。
3. 完整校准耗时至少 **2×** 加速。包含事件构造、排序、更新、求根和复核，不能只报告核心 kernel 时间。
4. 至少 6/9 个位置在预定的 2% 非劣范围内，任一位置退化不超过 10%。

这里是探索性门槛，不把 2 个 seed 的区间当成高置信度泛化证明。G1 需要同时输出置信区间或原始分布供诊断，但阶段判断以预注册效应量和一致性为主。

### 4.4 G1 后应做什么

- **PASS**：把代码、配置、Q、面板来源和结果同步到 AutoDL，先运行 G2 canary。
- **FAIL 且数学正确**：最多一次有明确假设的修正，例如改变事件更新实现；不追加无关模块。再次失败则停止这条主线。
- **INSUFFICIENT_EVIDENCE/RESOURCE_BLOCKED**：允许一个最多 4 GPU 小时的 AutoDL 环境/面板提取 probe；禁止启动完整模型×种子 sweep。probe 不是方法通过。

## 5. G2：AutoDL 完整模型 canary

### 5.1 完整 Transformer 浮点等价前置检查

在相同模型、输入、attention backend、dtype 下检查：原始模型 → 仅合法 Norm 融合 → 旋转模型，全部关闭量化。

- 对 LLaMA RMSNorm 路径关闭不等价的 embedding 行中心化。
- FP32 参考前向的 logits 相对 RMS 差异建议阈值 **1e-4**，固定小验证批上的平均 NLL 差异 **1e-4**。
- BF16/FP16 路径可额外记录较松的数值误差，但不能用低精度容差掩盖 FP32 方向性错误。
- 若阈值失败，先定位是等价构造、后端数值还是代码错误；禁止看完结果后直接改阈值。
- 必须通过实际 GPTQ 路径和 R1 checkpoint 加载；所有 R2 键齐全，`R1=Q.T`。

### 5.2 Canary 配置与决策

- 一个模型 LLaMA-2-7B；W4A4KV4；**固定 128×2048 校准样本**；2 个校准种子。
- 用独立开发集做 canary，不以最终 WikiText-2/C4 测试集反复调参。所有方法使用相同模型、量化配置、开发集、评估代码与数据顺序。
- 比较新方法、Hadamard、自己复现的 SpinQuant；记录 RTN → GPTQ 的收益迁移。
- 使用按完整序列/文档聚合的平均 NLL：`PPL=exp(mean NLL)`。两方法的相对 PPL 变化由 `exp(NLL_new-NLL_base)-1` 计算，不平均批次 PPL。

**准确率路线**：相比 Hadamard 的开发集 PPL 改善 ≥ **2%**；相比自己复现 SpinQuant 的 PPL 退化 ≤ **0.5%**；两个 seed 都满足退化上限；最终 GPTQ 没有使局部收益完全消失。

**效率路线**：相比 SpinQuant，两个 seed 的 PPL 退化均 ≤ **1%**，且包含采集/学习/融合/GPTQ的校准墙钟至少 **2×** 加速。只降低旋转训练时间但总 PTQ 时间不改善时，应报告局部加速，不能用来通过总校准效率路线。

此阶段建议先设 **12–24 GPU 小时**的总预算，具体由一次前向、一次旋转步骤和 GPTQ 单层实测修正。SpinQuant 原始 FP64 路径可能超过预算；超预算是待解决的工程/比较问题，不能用论文中的多卡时间填充缺失测量。

## 6. G3：启动完整实验矩阵之前

全部满足才批量运行：

- G2 已通过且结果不是 mock/smoke。
- 实际 GPU 型号、可见显存、MIG 状态和 CUDA 能力已核实；不依据租赁标题推断。
- CUDA GEMM、所使用的 FHT/量化扩展均已通过目标 GPU 的数值检查。
- 实测校准峰值保留至少 **15%** 显存余量，即 peak/visible ≤ 0.85；若不足，先降低缓存或流式处理，不降低最终量化位宽。
- 一个任务已经完成中断→恢复→相同结果的检查；日志和结果是原子写入，恢复不会覆盖成功运行。
- 主协议、开发集/测试集边界、模型与数据 revision、评估 task/metric、种子、角度预算、baselines 已冻结。
- 对完整实验计划给出基于实测的 GPU 小时预算；没有预算估计不启动全部模型。
- 模型分片大小与哈希、配置哈希、校准 token ID 哈希及代码 commit 已记录。

建议主矩阵：LLaMA-2-7B、原始 Meta-Llama-3-8B；W4A4KV4；3 seeds。主基线至少 Hadamard、SpinQuant 实际基线、同参数同目标 STE/搜索控制，以及一个可复现的 2026 年快速校准方法。完整主表成立后才增加 13B、额外位宽和更多样本数消融。

## 7. G4：何时足以写完整论文

### 7.1 所有路线共同要求

1. 两个主模型，每个 WikiText-2/C4，共 **4 个模型×PPL数据集单元**；每个至少 3 个校准 seed。
2. 六项零样本任务逐项报告，不能只报挑选后的平均。
3. 所有关键结论来自自己统一协议的结果；引用结果另表呈现。
4. 至少一个 2026 年方法与最近的 Givens/事件搜索思想有实质对照；不能只赢过 Hadamard 就认定方法创新。
5. 五项核心消融完成：双侧目标、动态尺度、交叉项/代理、尺度预算、安全筛选与增量更新。
6. 理论范围经过审查：不把 FP64 数值根当形式化认证；不把 RTN 单步结论推广成 GPTQ 或模型损失最优。
7. 新颖性复查更新到写稿日期；尤其复查 ParoQuant、TORQ、PiSO、OBCD、CROQuant 的后续版本。
8. 全局 R1 不增加在线算子；实际推理速度声明与运行后端一致。若只有浮点 fake quant，不报告 INT4 kernel 加速。

### 7.2 路线 A：准确率型方法论文

相对预先指定的**最强且同协议复现的竞争方法**，同时满足：

- 四个 PPL 单元按 log-PPL 等权汇总的几何平均相对改善 ≥ **1%**。
- 每个模型跨两数据集的平均改善 ≥ **0.5%**；任一 PPL 单元退化 ≤ **0.5%**。
- 主 NLL 差值（new − baseline）的 paired 95% CI 上界 ≤ **0**。
- 六任务均值提升 ≥ **0.5 个百分点**，paired 95% CI 下界 ≥ **0**。
- 没有依靠不一致的精度、分组、样本量、基础权重更新或额外在线算子获得优势。

这些是本项目愿意为准确率主张投入完整写稿的目标，不是所有可发表研究的统一最低线。若 PPL 明确改善而任务只有非劣，需缩小结论或按效率路线评估，不能补挑选更多任务直到均值变好。

### 7.3 路线 B：效率型方法论文

与**精度合格的竞争者中最快的一个**相比，同时满足：

- 每个 PPL 单元点估计退化 ≤ **1%**。
- 汇总 NLL 差值 paired 95% CI 上界 ≤ `log(1.01)=0.009950330853168092`。
- 六任务均值点估计退化 ≤ **0.3 个百分点**；paired 95% CI 下界 ≥ **−0.5 个百分点**。
- 包含激活采集、旋转校准、融合和 GPTQ 的总校准墙钟至少 **2×** 加速；同硬件、同数据、同精度，峰值显存不增加。
- 单独报告 solve-only 与 end-to-end PTQ，不能混淆。

不能只相对最慢的旧实现得到加速，就声称处于准确率—效率前沿。

### 7.4 统计方法与指标冻结

- PPL 不以 token 为独立样本计算普通 t 检验。保留文档/序列 ID；优先在文档层级进行 paired bootstrap，再处理校准 seed 层级。没有文档 ID 时，采用预先规定的连续大块 bootstrap，并明确近似与依赖性。
- 三个 seed 的原始值全部展示；不能因为 token 数量大而声称对校准随机性估计已经非常精确。
- 下游任务对相同题目做 paired resampling，任务均值固定等权。注意任务指标 `acc` 与 `acc_norm` 不可混用；在锁定的 harness commit 上验证具体 metric key 存在后冻结。
- 推荐 10,000 次 paired bootstrap；固定 bootstrap seed。一个预注册汇总 NLL 为主指标，其余作为分解指标，避免事后在四格中选最显著的一格。
- G4 的字段 `strongest_baseline_selection_frozen` 必须有预先选择规则及完整候选结果支撑，不能让程序随意选择较弱对手。

## 8. 哪个阶段开始写什么

| 达到阶段 | 可以写 | 还不能写 |
|---|---|---|
| G0 | 数学定义、命题、参考实现说明 | 真实 LLM 有效、资源优势 |
| G1 | 方法章节、机制图、局部实验证据 | GPTQ 完整模型提升、主表 SOTA |
| G2 | 完整模型结果草稿、工程实现段落 | 跨模型稳健性、最终论文主结论 |
| G3 + 部分主结果 | 完整论文结构和结果表模板 | 将缺失结果用外部论文数值混填 |
| G4 | 完整方法论文与投稿讨论 | 保证顶会录用或绝对未发表 |

若 G4 两条路线均失败，优先写清楚负结果、局部定理和适用边界。不要为了达到阈值增加 PCA、敏感通道分块、低秩补偿等无关模块。

## 9. 证据文件最小格式

每次 notebook 运行至少保存：`config.json`、`environment.json`、`manifest.json`、`metrics.json`、`stdout.log`、`gate_report.json`、校准与验证 token 的哈希，以及各 seed/层/任务的原始表。

证据的规范 `source_type` 为 G0=`synthetic_math`、G1=`real_layer`、G2–G4=`real_model`；另保留 `published`、`unit_test_fixture`、`estimate`、`not_run` 标注不可晋级的数据。兼容旧 `measured_cpu`/`measured_gpu` 时，还必须给出与阶段一致的 `scope`：G0=`math_reference`，G1=`real_layer_panel`，G2–G4=`full_model`。只有与当前阶段匹配的实测结果可以通过门槛。初始模板必须为 `not_run` 且 `metrics={}`，不得填入上一轮玩具结果假装真实层测量。

## 10. 指标计算的唯一约定

- NMSE改善百分比：`100 * (1 - nmse_new / nmse_baseline)`。当baseline误差低于预注册epsilon时，不用该比值制造巨大改善；报告绝对差异和退化标记，按预先规定的退化用例规则处理。
- PPL退化百分比：`100 * expm1(mean_nll_new - mean_nll_baseline)`；改善为 `100 * (1 - exp(mean_nll_new - mean_nll_baseline))`。
- 四格汇总的 `pooled_geomean_ppl_gain_pct`：先对每格每seed计算NLL，再对seed、四格分别等权平均NLL差值，最后用 `100 * (1 - exp(delta))`。不平均不同批次的PPL。
- `min_model_mean_ppl_gain_pct`：每个模型将其两数据集的NLL差值等权汇总再转成相对PPL改善，取两个模型较小值。
- `max_ppl_cell_regression_pct`：每个模型×数据集先汇总seed NLL，转成PPL退化，取最大值；不得只报告跨四格平均。
- 准确率百分点：`100 * (accuracy_new - accuracy_baseline)`，先固定每任务的metric key，再对六任务等权，最后按预注册方式汇总模型和seed。`0.5pp`不是相对`0.5%`。
- 加速比：`baseline_wall_seconds / method_wall_seconds`。GPU计时前后同步；编译/预热是否计入必须对双方一致。既报告包含编译的首次运行，也可另报稳态运行，不能挑较有利的一种。
- 所有95% CI使用 paired 数据和预定的层级/块重采样；输出原始单位。不能把百分比CI直接填入以`nats_per_token`为单位的字段。

JSON中的布尔字段也需要证据文件或可追溯检查记录。把布尔量手动全部设为true不会构成阶段证据；gate引擎是汇总器，不是独立实验真实性审计系统。

## 11. Gate CLI

```bash
python -m cellquant.gates evaluate --stage G1 \
  --evidence examples/G1_evidence_NOT_RUN.json \
  --output runs/gates/G1_report.json
```

默认即使没有通过也返回进程退出码0，以便notebook显示报告；这绝不代表阶段通过。启动真实全量前必须读取报告中的`status == "PASS"`，或者使用`--require-pass`，后者非PASS返回退出码2。缺失、None、NaN、Infinity、错误类型、错误阶段和非实测来源均不能通过。一个有效route通过时，另一路线缺字段不会阻止该有效路线，但全部common条件仍必须通过。
